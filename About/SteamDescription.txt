[h1]DefLoadCache[/h1]

Caches the result of RimWorld's mod XML loading and patching, so launches with an unchanged mod list skip that work.

[h2]What it does[/h2]
On startup, RimWorld reads every mod's XML files and applies every XML patch, from scratch, every launch. DefLoadCache saves the finished, patched result to disk. On the next launch with the same mod list, it loads that saved result instead of reading the files and running the patches again.

How much faster depends on how many mods you have, how many XML patches they use, and your disk speed. Measured on a 414-mod Combat Extended list under RimWorld 1.6:
[list]
[*] Launch that builds the cache: ~9:10 (normal speed plus a few seconds to save)
[*] Launch that uses the cache: ~2:40
[*] Cache size on disk: ~7 MB
[/list]

[h2]How it works[/h2]
[list]
[*] On a cached launch, these loading steps are skipped: reading mod XML files, checking patches for errors, and applying patches. The saved result is loaded in their place.
[*] Everything else still runs every launch: textures, sounds, translations, turning XML into defs, cross-reference resolution, Harmony patches and static constructors.
[*] The cache is keyed to your exact mod list: load order, mod versions, the RimWorld version, and the path, size and modification time of every file in each mod's Defs, Patches and Assemblies folders. Any change rebuilds it automatically.
[*] Each mod list profile keeps its own cache.
[*] Before using a cache, the mod checks that the file is intact and that the per-mod def counts match. A bad cache is deleted and rebuilt, and the game loads normally.
[*] Only startup loading is affected. Gameplay, defs and saves are unchanged, and you can add or remove the mod at any time.
[/list]

[h2]When you won't see a speedup[/h2]
Any launch that has to build the cache runs at normal speed, or slightly slower, because the result is also saved to disk. That happens:
[list]
[*] on the first launch after installing
[*] after adding, removing or reordering mods
[*] after any mod updates, including automatic Steam Workshop updates. A re-download counts even if the files' content didn't change. On large mod lists this can be frequent.
[*] after a RimWorld update
[/list]
The next launch with the same mod list uses the cache. The main menu shows whether the last launch used it.

An SSD and 16 GB+ RAM help. On a slow disk, reading and writing the cache takes a bigger share of the time saved.

[h2]Requirements[/h2]
[list]
[*] RimWorld 1.7: [url=https://steamcommunity.com/workshop/filedetails/?id=2009463077]Harmony[/url]. Prepatcher is not needed on 1.7.
[*] RimWorld 1.6: [url=https://steamcommunity.com/sharedfiles/filedetails/?id=2934420800]Prepatcher[/url]
[*] Place anywhere in your mod list after Harmony / Prepatcher.
[/list]

[h2]Compatibility[/h2]
Works alongside:
[list]
[*] Faster Game Loading, Image Opt: they speed up different loading steps (reflection, graphics, textures).
[*] Performance Fish, HugsLib: no known conflicts.
[*] [b]MissileGirl[/b]: compatible only with its XML cache (Gagarin) turned off. Both mods cache the same loading step, so running both caches at once will conflict. Its other features can run alongside DefLoadCache.
[/list]
Not compatible:
[list]
[*] [b]Visual XML Patches[/b]: it shows patches as they are applied. On cached launches patches aren't applied, so it has nothing to show. Use "Test without cache (next launch only)" for a launch when you need it.
[/list]

[h2]Known limitations[/h2]
[list]
[*] Mod settings are not tracked. If another mod's settings turn its XML patches on or off, use "Clear all cached data" in DefLoadCache's settings after changing them.
[*] Mods that generate or change def XML from code during loading, instead of through normal Defs and Patches files, may not be reflected in the cache.
[/list]

[h2]Settings[/h2]
Options > Mod Settings > DefLoadCache:
[list]
[*] Turn the mod on or off, or turn off skipping mod files / skipping patches separately
[*] Cache status, size and location
[*] Clear all cached data
[*] Test without cache (next launch only)
[/list]

[h2]Reporting problems[/h2]
If you are reporting a bug to another mod's author, reproduce it with "Test without cache" first. If you think DefLoadCache is the cause, please post your Player.log (or a link to it) in the comments. Each launch writes a DefLoadCache status block to the log that shows what the mod did.
